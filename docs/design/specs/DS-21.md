# DS-21 — Fewer sidebar links: five task sections, the pages inside them as tabs
Source docs: `docs/design/PLAN_DS-20_DS-21.md` (DS-21 and design decision 1, George 2026-10-16; on the plan branch, not on main yet); `docs/design/fas-screen-plan-part2.md` §1.2 nav; `docs/DESIGN.md` Part 2; `.claude/skills/design-polish/references/*`; DS-02 (shell), DS-18b (nav glyphs).
**Depends on:** DS-18b nav glyphs on main. **Sibling:** DS-20a (need map) runs in parallel; no shared files. **Budget:** ≤ 400 hand-written lines (D-012). **Before/after shots:** supervisor, from the preview.

## Purpose and users
The Workspace sidebar had ten links of equal weight; staff had to read all ten to find "where do I put this quarter's numbers". A sidebar link now names a task (house rule 4 of the plan), and the pages that serve one task sit as tabs on that section.

| Role | Gets |
|---|---|
| staff, admin | Workspace: Home · Insights · Data · Grants · Evidence packets; Board: Board dashboard; Admin: Overview (admin only). On a tab page, a row of tabs above the page content and the crumb "Section · Tab" |
| board_viewer | Unchanged: Board dashboard · County need map · Methodology, plain crumbs, no tabs |

## Scope (sub-packet a, the whole packet)
- New pure `lib/shell/sections.ts`: `SECTIONS`, `sectionsForRole(role)` (staff and admin only), `sectionFor(pathname, role)` on the canonical path (`canonicalizePath`, the same rule the crumbs and guards use).
- `lib/shell/nav.ts`: Workspace = 5 links; section links carry `section` and open their first tab; new `navActive(role, item, pathname)`; `crumbFor` returns "Data · Upload" on a tab page for staff and admin.
- New `components/shell/SectionTabs.tsx`, rendered by `ShellFrame` as the first child of `#main` when `sectionFor` matches.
- `components/shell/nav-icons.ts`: one glyph per visible href (9).
- Out of scope: moving or renaming any route, `lib/auth`, `middleware.ts`, role guards, page headers (the "WORKSPACE" eyebrow on `/data-freshness` stays; see Open questions 2).

## Audit (filled before code)
- First impression: ten Workspace links, three of them about data (Upload data, Enter data, Data freshness) split apart by Evidence packets; "Grant matches" and "Foundation grants" read as two products. The rail at 768–1023 shows ten glyphs with no grouping.
- Numbers inventory: none; the shell shows no numbers (the freshness chip is DS-05b and unchanged).
- Controls below 1024: sidebar links 44 px (kept); new tabs `min-h-11` (44 px) below 1024, 40 px at ≥ 1024.
- Layout: tabs sit inside the `Page` container, so they share the H1's left edge at every width (layout-parity rows unchanged, horizontal only). At 375 the Data row (four tabs) is one line that scrolls sideways inside its own box; the page never scrolls.
- States: the tabs are links, so loading (`loading.tsx` skeletons render under them), error and 403 states are the pages' own. A route that is not a tab shows no tab row.
- Tokens and styling: Tailwind token classes only (`border-border`, `border-primary`, `text-muted-foreground`, `duration-(--duration-fast)`, `ease-(--ease-out)`); no raw px or hex; no `globals.css` edit.
- Estimate: ~300 hand-written lines including this spec.

## States
Current tab: 2 px `--primary` underline, foreground text, medium weight, `aria-current="page"`. Other tabs: muted text, foreground on hover (120 ms, `--ease-out`; instant under reduced motion). Focus: the global 2 px ring, drawn inside the tab so the scroll box never clips it. At 375 the Data row (about 400 px) is wider than the screen; on load the row scrolls itself so the current tab is fully in view (the accessibility pass found Methodology starting off-screen).

## Trust rules
No number, source or state is added. Every URL is unchanged, so bookmarks, guards and board-viewer access are untouched.

## Accessibility
`<nav aria-label="Data pages">` inside `main`, a list of links, `aria-current="page"` on the current tab and on the active section link. Reading order: tabs, then the page H1. 44 px targets below 1024. No sideways page scroll at 375. axe 0 serious or critical on every tab route at 375/1024/1440.

## Decisions
1. Tabs render inside `#main` from `ShellFrame` (smallest diff, inside the `Page` container so they align with the H1 and stay visible under each route's `loading.tsx`), not in the sticky top bar.
2. Crumbs for tab pages are derived from `SECTIONS` for staff and admin; the `CRUMB` map keeps plain page names, which board viewers (and any non-section role) still read.
3. Underline tabs, not pills: the quietest form that still marks the current page; the 1 px rule under the row is the only chrome.
4. `HIDDEN_LABELS` still lists "Matches" (a screen-plan sidebar item); the new "Matches" tab is not a sidebar link, so the hidden-label guards still hold.
