## Purpose and users
Explain how the county need score is built — inputs, weights, vintages, limits — so staff can cite it in grants and the board can trust the map.

| Role | Gets | Doesn't get |
|---|---|---|
| staff | Latest **approved** methodology; draft notice if a newer unapproved config exists; version history (DS-08b); link to `/need-map` | Weight editing; drafts on the map |
| admin | Same as staff; `Edit weights` only if `/admin/need-score` exists | — |
| board_viewer | Same approved methodology, read-only | Draft notice, draft history rows, admin links |

Public data and config only. No FAS case data.

**/need-map** — Unhide action `Methodology` → `/methodology`.

**Version line** — `Version <version>, approved <Mon YYYY>` (seed: `Version v2-synthetic, approved Oct 2026`). If version id contains `synthetic` or env ≠ production: badge `Synthetic data`. Draft preview (staff/admin): `Version <version> · Draft — not approved · created <Mon YYYY>`.

**Draft notice** (staff/admin only; board never) — Title `Newer draft on file`. Body `Version <draftVersion> was created <Mon YYYY> and is not approved. The map and this page still use the approved version.` Button `Review draft` only if `/admin/need-score` exists.

**TOC** — `How we calculate it` · `Inputs` · `Weights` · `Vintages` · `Limits` · `Version history` (last when DS-08b ships).

**How we calculate it** (h2)
- Plain: `For each Utah county we turn every input into a z-score (how far that county sits from the statewide average, in standard deviations). We multiply each z-score by its weight, add them up, and rank counties from highest to lowest score. The rank is relative — a high score means higher need than other Utah counties on these inputs, not a fixed level of need.`
- Precise (mono): `score_c = Σ_i ( w_i × z_i,c )` where `z_i,c = (x_i,c − μ_i) / σ_i` over counties with a published value for input `i`.
- Note: `Counties missing a required input for this version are Not published and get no rank (same rule as the need map).`
- If approved config is single-input synthetic: `This approved version (v2-synthetic) uses a placeholder single input for previews. Real multi-input weights are set by FAS policy.`

**Inputs** — Columns `Input` · `Source` · `Vintage` · `As of` · `Status`. Caption `Public inputs for need score version <version>`. List **only** keys present in `need_score_config.weights` (seed: `uninsured` → label `Uninsured rate`, source `Census SAHIE`). Unknown keys: raw key in mono + muted `Unlabeled input`. Never invent values; never-succeeded source → `—` + `Not published`. PRD C4's full set (HRSA HPSA-MH, CDC PLACES, Utah Courts+ACS, optional SAIPE/VetPop) appears only when those keys exist in an approved config — do not hardcode rows that the config does not contain.

**Weights** — Columns `Input` · `Weight` · `Share of total`. Footer `Total` · `<sum>` · `100%` (or actual). If weights clearly do not sum to 1 (or 100 on a points scale): `Weights in this version do not sum to 1 (sum = <sum>).` — display only; UI does not auto-normalize. Seed: `Uninsured rate` · `1` · `100%`. Caption `Weights for version <version>`.

**Vintages & freshness** (h2 `Vintages and freshness`) — Intro `Each input carries the vintage the source published and the date of our last successful load.` Per input: source line + `FreshnessChip` (D-021) or `Not published`. Failed keeps last success if any. Line when scored counties < 29: `<k> of 29 counties are Not published for this version.`

**Limits** (h2 `What this score cannot tell you`)
1. `It is not a measure of how well FAS is doing.` — public county indicators only, not FAS cases or outcomes.
2. `It is county-level only.` — no cities, ZIP codes, tracts, or addresses.
3. `It is a relative ranking among Utah counties, not an absolute level of need.`
4. `Small-population counties are noisier.` — survey estimates swing more; treat thin counties carefully.
5. `Vintages differ by source.` — one input may lag another; each row's vintage stays visible.
6. `Placeholder weights may be in use.` — synthetic or single-input configs are labeled as such until FAS sets production weights.

**SourceFooter** — `Public sources: <names> · Need score version <version> · as of <Mon YYYY>` (+ ` · Synthetic data` when applicable).

**Version history** (DS-08b) — h2 `Version history`. Columns `Version` · `Created` · `Status` · `Weight sum` · `Counties scored`. Status `Approved` / `Draft — not approved`. Board: approved only.

## Trust rules
- Every input shows source + vintage + as-of; Version line always shows version id + approval state.
- Weights sum is displayed; mismatch called out in text.
- No real FAS client data; seeds/previews synthetic (PRIVACY §1; D-015).
- No FAS person counts here → n<11 `SuppressedCell` N/A; public gaps are `Not published`, never 0.
- Formula in plain words **and** precise form. Never color alone. Dates: month/year. FAS Evidence branding only.
