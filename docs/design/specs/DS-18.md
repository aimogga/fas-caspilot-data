# DS-18a — Upload data: error cells that explain themselves, a stepper and dropzone in tokens, batch statuses in words
Source docs: `docs/design/POLISH_PLAN.md` row DS-18a/b; `docs/design/targets/visual-direction.md` (shared rules: eyebrow → sentence → source line, one accent, type steps); `docs/design/fas-screen-plan-part2.md` §4 P1-3 (upload wizard, mockup `p1-upload-mapping.png`, the five-step plan the three-step build condenses); F-301 (the wizard as built); DS-09 (explain kit); DS-14 (`PageSkeleton`); DS-16a (status words beside a badge in one `Hint`); `.claude/skills/design-polish/references/*`.
**Depends on:** DS-09 explain kit and DS-14 `PageSkeleton` on main (0de2ff2). **Budget:** ≤ 400 hand-written lines (D-012). **Before and after shots:** taken by the supervisor from production and the preview (this shell has no Docker, Supabase or preview). **DS-18b** (`/staff/entry`, `AggregateBadge`, nav icons) appends its own section to this file.

## Purpose and users
The page a staff member uses to bring a spreadsheet of FAS records into the evidence base without saving a single bad row. Every error must say, in words, what is wrong with that cell; every past upload must say, in words, whether its rows count today.

| Role | Gets |
|---|---|
| staff, admin | The wizard (choose file → match columns → preview) and the team's newest 20 uploads with a Roll back action |
| board_viewer | 403 (unchanged) |

## Scope (sub-packet a only)
1. Preview error cells: the native `title` becomes a `Hint` on the word `Error`, so pointer hover, keyboard focus and tap show the same reason; `data-error` stays for tests; the helper sentence stops promising a "tooltip".
2. Stepper: three numbered discs with the current step filled in the accent, finished steps ticked, upcoming steps muted; tokens only; the current step keeps `aria-current="step"`.
3. Dropzone: the file input sits inside a dashed card with one helper sentence; the native input stays visible (keyboard, 44 px, browsers accept a dropped file on it), nothing invented.
4. `BatchList`: the status badge and its words become one `Hint` per row in plain language (`Saved`, `Rolled back`); the type column reads `Case records`, never a bare key or `—`; the batch reference carries a `Hint`; rows are ≥ 44 px tall below 1024.
5. Page header: the workspace eyebrow and a serif headline in words, `Add FAS records from a spreadsheet`, with a one-sentence description that ends on the trust rule.
6. `app/(app)/staff/intake/loading.tsx` with `PageSkeleton` (two blocks sized like the wizard and the list).
Out of scope: `/staff/entry`, `AggregateForm`, nav icons (DS-18b); drag-and-drop JavaScript; saved mappings, a right rail or a five-step stepper (screen plan, later); any schema change.

- Eyebrow `WORKSPACE` (the shared workspace eyebrow every staff route uses). H1 `Add FAS records from a spreadsheet`. Description: `CSV only for now. Download a template, fill it in, upload it, match the columns and check the preview. Nothing is saved until you choose Save.`

- Reference hint: `The first 8 characters of this upload's id. Quote it when you ask about an upload.`

## States
Step 1, 2, 3; file problem (alert); missing required fields (alert); preview with and without errors; saved; save error; batch list empty; batch list rows saved and rolled back; rollback error; loading skeleton; county list error; 403.

## Trust rules
Every word in the batch list comes from `upload_batch` rows under RLS; dates are the day a batch was saved (operational metadata, no family data). Error reasons are the validator's own messages. No count or status is invented; a missing type says `Not recorded`.

## Accessibility
Every new trigger is the kit's 44 px button below 1024 with the visible focus ring; hover text = focus text = tap text; status never by colour alone (badge glyph + word + sentence); the stepper's current step is `aria-current="step"`; `th scope` kept; `scrollWidth` ≤ 375; axe 0 serious or critical at 375, 1024 and 1440.

## Decisions
- `Committed` becomes `Saved` on screen: the button says `Save`, the confirmation says `Saved n rows`, so the list uses the same word. The stored status value is unchanged; `data-batch` rows keep working.
- One `Hint` per error cell rather than an `ExplainLayer`: a preview shows at most 20 rows, and error cells are the exception, so the Radix-root count stays small and the kit face is the one every other page uses.
- No drag-and-drop script: a visible native file input inside the dashed card already accepts a dropped file in every current browser, so the card is honest without new code.
- The eyebrow stays `WORKSPACE`: every staff route shares it (DS-15, DS-16a and their tests), and the nav plus breadcrumb already say `Upload data`; the headline carries the words.
- Stepper step 2 is renamed `Match columns` to match the helper sentence ("Match each field to a column"); the heading `Step 2 of 3: Match columns` follows.
