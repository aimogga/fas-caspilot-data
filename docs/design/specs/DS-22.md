# DS-22 — Need map: one county at a time (county picker)

**Source docs:** `docs/design/specs/DS-20.md`, `docs/design/fas-screen-plan-part2.md` §4, `docs/design/targets/visual-direction.md` (need map). **Depends on:** DS-20a, DS-20b (merged). **Supersedes:** DS-20c (trimmed table, PR #292, not merged).

## Purpose and users
George looked at the live page: the 29-row table is the clutter. The page now shows **one county at a time**. A map click and a menu both drive the same county panel. Staff, admin and board viewers see the same page.

## Scope
- New `components/need-map/CountyPicker.tsx`: native `<select>` labelled "Choose a county", first in the county panel (above the county name), both states.
- `CountyPanel`: picker in the header; before a pick, the "Highest need" top five stays with a new sentence.
- Page: no `NeedTable`, no `RankedList` (the page stops rendering them; the files and their tests stay for a cleanup packet, see PR split); the source footer stays under the map.
- `lib/need-map/panel.ts`, `query.ts`: court filings get a plain topic and labels.

## Components (existing only)
`CountyPanel`, `NeedMap`, `MapSelect`, `ExplainLayer`/`ExplainCard`, `Hint`, `Provenance`. New: `CountyPicker` (a client component like `FasFilter`).

## Exact copy
- Label: `Choose a county`. Placeholder option: `Select a county…`. A county with no need score: `<Name> County (no score)`.
- Panel sentence before a pick: `Pick a county on the map or from the menu above to see why it ranks where it does.`
- Page description: `Each county is ranked against the other 28 on public measures such as poverty and uninsured rates. Darker means more need. Pick a county on the map or from the menu to see why it ranks where it does.`
- Courts: topic `Court filings`; labels `Court filings (all courts)`, `(district)`, `(justice)`, `(juvenile)`; source name `Utah State Courts` (was the code `ut_courts`). Unknown sources still fall back to their own name.
- The hover card for an unscored county now ends `Its public measures are in the county panel.` (it said "in the table").

## States
- No pick: placeholder selected, "Highest need" top five. Pick: the county's name is the option's value; rank line, key measures, "All measures" as in DS-20b.
- `?fas=1`: options are the FAS counties only. A non-FAS county picked on the (dimmed) map stays in the list so the menu can show it.
- Unscored county: option says `(no score)`; panel says so and why (unchanged).
- Loading, error, empty: unchanged (page skeleton, `ErrorState`, `EmptyState`).

## Trust rules
Numbers unchanged and still from the database. Nothing new is shown that the app does not have. Hatch, "Not published" and "Not available yet" wording unchanged.

## Accessibility
- The map's **table equivalent is now the picker plus the panel**: every county's every measure is reachable by keyboard through the select and the "All measures" disclosure, with the same source and as-of words. The sr-only `need-map-summary` (top 3, bottom 3, not-published count) stays as the map's `aria-describedby`.
- Native `<select>` with a visible `<label for>`; 44 px high below 1024 (`h-11` everywhere); visible focus ring; no JS needed beyond the navigation.
- `design:accessibility-review` result: label and name match, focus ring from tokens, no colour-only meaning (the option text says "(no score)"), reflow at 320 px (select shrinks, `min-w-0`), no keyboard trap.

## PR split
Two packets. This one: picker, page change, courts, e2e rewrite (under the 400-line cap). Cleanup packet: delete `NeedTable.tsx`, `RankedList.tsx`, `indicatorCell` and the tests that only they use (about 190 deleted lines), which would have taken this one to 441.

## Decisions
- Native select over a custom combobox (best mobile, keyboard and screen-reader behaviour). The URL from the menu is `?fas=1&county=<fips>` (query order follows the current URL, like the map).
- `NEED_TERMS`, `scoreCell`, `FAS_BADGE`, `needTerm`, `splitMoe`, `moeWords` stay: the panel and the packets still use them. `indicatorCell` is used only by the (now unrendered) table; it goes with it in the cleanup packet.
