# DS-04 — 403 / 404 / error pages + role redirect
Source docs: gated on design-sources PR (4) — mockups (must be merged first).
**Depends on:** DS-03. **Budget:** ≤ 400 lines. **Mockup:** `p0-403.png`.

**Scope**
- **Role redirect:** `/` redirects staff to `/staff`, admin to `/admin` and board_viewer to `/board` (these become `/home` and friends later). The dev health UI moves off `/`, or is removed, since `/api/health` stays.
  - A user with no role sees an "Account not set up" state.
  - Post-login without a `redirect` param lands on the role home.
  - Update `RULES` and the unit tests.
- **403:** middleware returns a *real 403 status* (fixes #13). Rendered in the shell for signed-in users. Shows "You don't have access to <area>", the user's role, "Go to <home>", "Ask an admin for access", the requested path in mono, and "This attempt was logged." (log only if audit insert is available; otherwise drop that line).
- **404:** `app/not-found.tsx` using the same card pattern.
- **Error:** `app/error.tsx` and `global-error.tsx` with retry and a reference id, never a stack trace.
- **Session expired:** returns to `/login?redirect=…` with an info alert.

**Acceptance**
1. e2e: board → `/staff` returns status 403 and shows the card; each role's `/` goes to its home.
2. Unit: `isPublicRoute` negative test for `/api/healthz` (#13).
3. Screenshots (403 as board, 404, error) at 1440; axe clean.

## Mobile layout (375px; below 768px)
Mockup: `docs/design/mockups/p0-403-375.png` (404 and error pages use the same layout).
- Authed users see the DS-02 mobile top bar; signed-out users see a 56px bar with the wordmark only.
- Message card: width 100% inside 16px page padding, padding 24px 20px, centered text.
- Icon tile 48px; eyebrow "ERROR 403 · NO PERMISSION" 13px caps; heading Source Serif 4 22px, wraps.
- Actions stack vertically, full width, 44px high: primary (role home, e.g. "Go to Board dashboard") first, secondary ("Ask an admin for access" / "Try again") second, 12px gap.
- Footnote (requested path in mono + "This attempt was logged.") 13px, wraps; long paths break with `overflow-wrap:anywhere`.
- Role redirect is unchanged on mobile.
- Acceptance additions: 403/404/error screenshots at 375/1024/1440; `scrollWidth <= 375`; HTTP status still 403/404/500.

**Mobile hard requirements (QA-checked at 375):** labels stacked above full-width fields; ≥ 16px side padding on login and pages; input text ≥ 16px; every tappable control ≥ 44×44px; no horizontal scroll. Contrast meets WCAG 2.2 AA (text 4.5:1, large text/UI 3:1).

## Page container adoption (intended layout change)
These screens adopt the DS-01c `Page` container (`[data-slot=page]`). Signed in, it sits in the DS-02 shell's main column; signed out, it sits under a wordmark-only bar with no sidebar. This replaces the legacy bare `<div>` layout on `/403`, `/404` and the error page, and the dev placeholder on `/` (which becomes the role redirect). Gutters are 16 / 24 / 32 as in DS-01c.

- **What 1200 means.** 1200px is the `Page` container's **outer** max width, gutters included (this matches DS-01c and PR #37). The content box is 1200 − 2 × 32 = **1136** at most. All figures below are measured from the viewport's left edge, with the sidebar or rail included.

**Expected visual change. This is intended; QA judges against it, not pixel parity with main.** `/403`, `/404` and the error page change from bare text to a centred message card inside `Page`. `/` becomes a redirect to each role's home. The role redirect is a behaviour change too, and is intended.

**Signed in** (e.g. a staff user on `/403`, inside the shell):

| Viewport | Left of main column | Main column | Gutter | h1 left edge (viewport x) | Content width |
|---|---|---|---|---|---|
| 375 | top bar only, no sidebar | 375 | 16 | **16** | **343** |
| 800 | 56px rail | 744 | 24 | 56 + 24 = **80** | 744 − 48 = **696** |
| 1024 | 256px sidebar | 768 | 32 | 256 + 32 = **288** | 768 − 64 = **704** |
| 1440 | 256px sidebar | 1184 | 32 | 256 + 32 = **288** | container 1184 (under the 1200 cap), content 1184 − 64 = **1120** |

**Signed out** (wordmark bar, no sidebar, e.g. `/404` or the error page when logged out):

| Viewport | Gutter | h1 left edge | Content width |
|---|---|---|---|
| 375 | 16 | **16** | **343** |
| 800 | 24 | **24** | **752** |
| 1024 | 32 | **32** | **960** |
| 1440 | 32 | (1440 − 1200) / 2 + 32 = **152** | container 1200, content 1200 − 64 = **1136** |

- **Playwright (signed in):** assert the h1 left edge is 16 / 80 / 288 / 288 and the content width is 343 / 696 / 704 / 1120 at 375 / 800 / 1024 / 1440, with the container 1184 wide at 1440.
- **Playwright (signed out):** assert the h1 left edge is 16 / 24 / 32 / 152 and the content width is 343 / 752 / 960 / 1136, with the container 1200 wide at 1440. `scrollWidth` equals the viewport at every width, in both cases.
- **Layout-parity test (required).** This PR updates `tests/e2e/layout-parity.spec.ts` with the new expected h1 left edge and content width for its own screens (`/403`, `/404`, the error page, and `/` as a redirect), using the figures above. It must not delete the test, skip any screen, or loosen tolerances. Screens this PR doesn't move (none: every screen is on `Page` after this PR, so all entries are updated to their `Page` values, signed in and signed out) keep main's values unchanged.
- **Body padding (this is the last move).** This PR moves the last remaining legacy screens onto `Page`, so it removes the DS-01a global `body { padding-inline: 16px }` and the interim `body:has(> [data-slot=page]) { padding-inline: 0 }` rule. After this PR, no screen is left on the legacy layout. Verify the ≥ 16px mobile gutter on every screen at 375.
- Before/after screenshots at 375 / 800 / 1024 / 1440 are attached to the PR.

## Split and approved deviations (QA record)
- **Split:** DS-04a (PR #62, squash-merged at 21c693b) shipped the role redirect, the real 403 status, the session-expired alert and the dev health move. DS-04b (PR #64) ships the message card, the signed-out wordmark bar, the 403/404/error pages, body-padding removal and the e2e.
- **404 only through `notFound()`:** unknown paths stay deny-by-default in middleware; prefix guards are tracked in #63.
- **"This attempt was logged." dropped:** no audit insert exists yet, so the line would promise behaviour the app doesn't have.
- **Guidance is plain text:** the 403 shows "Ask your FAS admin to change your role." as text, not as a link or button.
- **Axe on `/403` (landmark-one-main, region):** the legacy bare `<div>` page had no `main` landmark; `/403` now renders inside the shell's `Page` (`main`), and `status-pages.spec.ts` runs axe on it at 375/1024/1440.
