# DS-04 — 403 / 404 / error pages + role redirect
Source docs: see DESIGN_WORKFLOW.md → Source documents (land before DS-01b).
**Depends on:** DS-03. **Budget:** ≤ 400 lines. **Mockup:** `p0-403.png`.

**Scope**
- **Role redirect:** `/` redirects staff to `/staff`, admin to `/admin` and board_viewer to `/board` (these become `/home` and friends later). The dev health UI moves off `/`, or is removed, since `/api/health` stays.
  - A user with no role sees an "Account not set up" state.
  - Post-login without a `redirect` param lands on the role home.
  - Update `RULES` and the unit tests.
- **403:** middleware returns a *real 403 status* (fixes #13). Rendered in the shell for signed-in users. Shows "You don't have access to <area>", the user's role, "Go to <home>", "Ask an admin for access", the requested path in mono, and "This attempt was logged." (log only if audit insert is available; otherwise drop that line).
- **404:** `app/not-found.tsx` using the same card pattern.
- **Error:** `app/error.tsx` and `global-error.tsx` with retry and a reference id, never a stack trace.
- **Session expired:** returns to `/login?redirect=…` with an info alert.

**Acceptance**
1. e2e: board → `/staff` returns status 403 and shows the card; each role's `/` goes to its home.
2. Unit: `isPublicRoute` negative test for `/api/healthz` (#13).
3. Screenshots (403 as board, 404, error) at 1440; axe clean.

## Mobile layout (375px; below 768px)
Mockup: `docs/design/mockups/p0-403-375.png` (404 and error pages use the same layout).
- Authed users see the DS-02 mobile top bar; signed-out users see a 56px bar with the wordmark only.
- Message card: width 100% inside 16px page padding, padding 24px 20px, centered text.
- Icon tile 48px; eyebrow "ERROR 403 · NO PERMISSION" 13px caps; heading Source Serif 4 22px, wraps.
- Actions stack vertically, full width, 44px high: primary (role home, e.g. "Go to Board dashboard") first, secondary ("Ask an admin for access" / "Try again") second, 12px gap.
- Footnote (requested path in mono + "This attempt was logged.") 13px, wraps; long paths break with `overflow-wrap:anywhere`.
- Role redirect is unchanged on mobile.
- Acceptance additions: 403/404/error screenshots at 375/1024/1440; `scrollWidth <= 375`; HTTP status still 403/404/500.

**Mobile hard requirements (QA-checked at 375):** labels stacked above full-width fields; ≥ 16px side padding on login and pages; input text ≥ 16px; every tappable control ≥ 44×44px; no horizontal scroll. Contrast meets WCAG 2.2 AA (text 4.5:1, large text/UI 3:1).
