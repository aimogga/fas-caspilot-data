# DS-05 — Data freshness panel
Source docs: `fas-screen-plan.md` §4 (Data freshness / F-209), §1.2 Workspace nav, §3 trust patterns; `fas-product-inventory.md` F-209 + screen #10; `design-system-v1.md` FreshnessChip / table / SourceFooter.
**Depends on:** DS-04 (shell + Page + role guards) and F-201 data (`source_registry` / `ingest_run` readable). **Budget:** ≤ 400 hand-written lines (D-012). **Mockup:** none dedicated yet — derive from design-system + screen plan; Playwright screenshots at 375 / 1024 / 1440 are the acceptance.

**Scope**
- Route: `/data-freshness` (F-209). Signed-in **staff** and **admin** only. `board_viewer` hitting the URL gets a real **403** (DS-04 card). Add the route to `RULES` in `lib/auth/role-guards.ts`.
- Unhide Workspace nav item **"Data freshness"** for staff and admin (already in IA; currently hidden until the route exists). Board nav stays unchanged — no freshness page link.
- Page inside DS-02 `AppShell` + DS-01c `Page` / `PageHeader`.
- Table of public sources from `source_registry` joined to latest successful `ingest_run` (and latest run of any status for admin detail).
- Wire the DS-02 top-bar **global freshness chip** placeholder: show aggregate status (text + icon) for **every** signed-in role, including board. Chip links to `/data-freshness` for staff/admin; for board it is non-navigating (or links to `/need-map` — prefer non-navigating `button`/`span` with the same chip chrome so board never hits 403 from the chip).
- Reuse: `Page`, `PageHeader`, `FreshnessChip`, `EmptyState`, `ErrorState`, `SourceFooter`, `Skeleton`, DS-01c ResponsiveTable stack helper. No new trust primitives.
- Do **not** build ingest, pause/resume, need map, or methodology here (see Out of scope).

### Table columns

| Column | Staff | Admin | Notes |
|---|---|---|---|
| Source | ✓ | ✓ | `source_registry.name`; secondary muted line = owner when present |
| Latest vintage | ✓ | ✓ | From latest successful indicators / run metadata; "—" if none |
| Last successful run | ✓ | ✓ | Date only, `Oct 12, 2026` (public-source run metadata, not FAS case data, so a day is allowed; no time of day). "Never" if null |
| Cadence | ✓ | ✓ | Humanized `cadence` (e.g. Monthly, Quarterly, Annual) |
| Status | ✓ | ✓ | `FreshnessChip`: Current / Stale / Failed / Not published |
| Latest run | — | ✓ | Link to admin run detail when F-201 route exists (`/admin/sources` or `/admin/ingest-runs/:id`). If that route is not shipped yet, show mono run id **without** a dead link (same hide-until-route rule as DS-02). Staff never see this column. |

Sort default: Failed → Stale → Not published → Current, then Source A–Z. Sticky header, comfortable density (44px rows below 1024; compact allowed at ≥ 1024).

### Exact copy

**PageHeader**
- Eyebrow: `WORKSPACE`
- H1: `Data freshness`
- Description: `Latest vintage, last successful run, and status for each public data source.`

**Status words** (must match `FreshnessChip`; never color alone)
- Current — glyph ✓ · soft success
- Stale — glyph ◷ · soft warning · optional suffix ` · N days` when age is known
- Failed — glyph ✕ · soft destructive · word `Failed` (or `Last run failed` in the chip long form)
- Not published — dashed/hatched chip · words `Not published` when `last_success_at` is null and no vintage exists (never show as 0 or invent data)

**Empty (E)**
- Title: `No sources registered yet`
- Body: `Public data sources will appear here after the source registry is set up.`
- Action (admin only, and only if `/admin/sources` exists): `Go to data sources` → `/admin/sources`. Staff: no action button (or muted "Ask an admin to register sources.").

**Loading (L)**
- `PageHeader` static; table region = 6–8 skeleton rows matching column layout (no layout shift). Shimmer off under `prefers-reduced-motion`.

**Error (Er)**
- `ErrorState` title: `Couldn't load data freshness`
- Body: `Something went wrong loading the source list. Try again.`
- Button: `Try again` (retry fetch). Include support reference id when available. Never raw Supabase/env text.

**Permission-denied (PD)**
- Board (and any non-staff/admin) → DS-04 403 card for area "Data freshness". Real HTTP 403.

**SourceFooter** (under the table card when ≥ 1 source)
- `Public sources · as of <most recent last_success_at across sources>`
- Opens provenance sheet pattern when DS-01c provenance is wired; otherwise footer text only is enough for this PR.

**Top-bar aggregate chip copy**
- All Current (or only Current sources): `Public data updated <relative or date>` with Current glyph — e.g. `Public data updated 2 days ago`
- Any Stale, none Failed: `Stale · N days` (N = age of oldest stale success, or worst source)
- Any Failed: `Last run failed` (Failed glyph)
- Mix with Not published only (no success yet): `Not published`
- No sources / still loading: chip **hidden** (same as DS-02 placeholder behavior)
- Priority for aggregate: **Failed > Stale > Not published > Current**

**Buttons / links**
- `Try again`
- `Go to data sources` (admin, conditional)
- Admin run link label: `View run` (or the short run id as the link text in mono)

### Tablet (800, rail)
- Same as desktop, but the table keeps five columns (admin: six) in comfortable density with 44px rows; Cadence wraps under Source as a muted line if the row would overflow. No page-level horizontal scroll.

### Desktop (≥ 1024)
- `PageHeader` with title left; optional summary cluster right: count of sources + one aggregate `FreshnessChip` matching the top bar.
- Table in a `card` full content width; numeric/date columns tabular; Status column uses `FreshnessChip`.

### Mobile (375; below 768)
- Header stacks; description full width.
- Table uses DS-01c **stack** pattern: each source is a card-like row (Source as full-width label row; Vintage / Last success / Cadence / Status as label→value pairs; admin "View run" is a 44px target). Page itself never scrolls horizontally; if a non-stack fallback is used, scroll is inside the card with a visible "Scroll →" hint.
- Top-bar chip sits in the second breadcrumb row (wraps under breadcrumbs per DS-02); still text + icon.

## States (complete)

| State | What the user sees |
|---|---|
| Empty | EmptyState copy above; chip hidden |
| Loading | Skeleton rows; chip hidden or prior value not flashed incorrect — prefer hidden until first settle |
| Error | ErrorState + Try again; chip hidden |
| Current row | FreshnessChip Current |
| Stale row | FreshnessChip Stale · N days; still show last vintage and last success (do not blank data) |
| Failed row | FreshnessChip Failed; show last success if any, else Never; do not substitute fabricated values |
| Not published | FreshnessChip Not published; vintage "—"; last success "Never" |
| Paused source (`status=paused`) | Still listed; muted "Paused" text beside the source name; status chip still reflects last run / freshness |
| Admin vs staff | Same rows; admin-only Latest run column/links |
| Board on URL | 403 PD card |

**Stale rule (designer call):** a source is Stale when `last_success_at` is older than one cadence interval past due (e.g. monthly source with last success > ~31 days ago). Failed when the latest `ingest_run` has failed status regardless of age. Not published when there has never been a successful run. Current otherwise. Encode in `lib/freshness/status.ts` with unit tests; tweak thresholds in one place.

## Accessibility
- Real `<table>` with `<th scope="col">` on desktop/tablet; stacked rows on mobile still expose name/value text (or a table alternative).
- Status never color alone — `FreshnessChip` always renders glyph + word (DS-01c unit rule).
- Sortable headers (if sorting UI is included) use `aria-sort`; if sort is fixed server-side only, no sort buttons required in this PR.
- axe: 0 serious/critical at 375 / 1024 / 1440, sheet open and closed on mobile.
- Every tappable control ≥ 44×44 below 1024 (Try again, run links, nav).
- `scrollWidth <= 375` on the page.
- Focus visible ring; landmarks via shell; breadcrumb includes "Data freshness".
- Contrast WCAG 2.2 AA (text 4.5:1; large/UI 3:1) including soft chip backgrounds with their foreground tokens.

---

## Trust rules
- Every row status is text + icon (`FreshnessChip`), not color alone.
- Stale and Failed are explicit labels; do not hide failed sources or silently show old data as current.
- Not published is labeled; never interpolated as 0.
- Table card carries `SourceFooter` with aggregate as-of.
- No branding other than FAS Evidence anywhere (UI, title, metadata).
- No purple, no gradients.
- Public data only on this screen — no case-level FAS records, so n<11 suppression does not apply here (there are no counts of people). County-level only is N/A (sources are listed, not places).
- Dates: vintages are shown as published (year, or month/quarter); run dates are day-precision without time.
- No AI output on this screen, so no DRAFT banner.
