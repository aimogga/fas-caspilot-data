# DS-03 — Login
**Depends on:** DS-02 (wordmark component). **Budget:** ≤ 400 lines. **Mockup:** `p0-login.png`.

**Scope**
- Split layout at lg and above. Left: card, max 400px, with wordmark, H1 "Sign in to FAS Evidence", Email, Password with a Show/Hide toggle (`aria-pressed`), a full-width lg primary button ("Signing in…" while loading), and a "Forgot password?" link (hidden until a reset route exists; tracked as a follow-up). Right: `--sidebar` panel with the value line and the privacy note. Below lg: single card.
- Errors: map Supabase errors to the generic "Email or password is incorrect." Rate-limit message. A missing config shows the Alert "Sign-in is temporarily unavailable." with no env var names.
- Suspense fallback is a skeleton card.
- Keep `safeRedirect` and the `?redirect=` param.

**Acceptance**
1. e2e: bad password shows the generic alert (`role="alert"`), and focus moves to it.
2. e2e: success honors `redirect`.
3. Unit: the error mapper never returns raw text.
4. Screenshots at 1440 and 1024; axe clean.

## Mobile layout (375px; below 768px)
Mockup: `docs/design/mockups/p0-login-375.png`.
- Split layout collapses to one column; the form comes first, the "Public data to proof" panel moves below it.
- Form column: padding 28px 20px (side padding never below 16px); wordmark + org line at top; card width 100%.
- H1 "Sign in to FAS Evidence" Source Serif 4 28px, may wrap to two lines; subtitle 15px.
- Error alert full width, `role="alert"`, above fields.
- Labels above inputs; inputs 48px high, 16px text; "Forgot password?" link sits on the password label row with a 44px tall hit area; Show/Hide toggle 44×44.
- Sign in button full width, 48px.
- Info panel: top border instead of left border, padding 24px 20px; quote at 22px serif; the protected-data note stays; the decorative sample card is hidden.
- No horizontal scroll; keyboard opens without the submit button being obscured (form scrolls).
- Acceptance additions: screenshots at 375/1024/1440; `scrollWidth <= 375`; inputs computed font-size ≥ 16px.

**Mobile hard requirements (QA-checked at 375):** labels stacked above full-width fields; ≥ 16px side padding on login and pages; input text ≥ 16px; every tappable control ≥ 44×44px; no horizontal scroll. Contrast meets WCAG 2.2 AA (text 4.5:1, large text/UI 3:1).
