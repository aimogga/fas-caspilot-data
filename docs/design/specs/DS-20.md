## Purpose and users
The page answers one question: where is the need greatest? A board member should see the answer before touching anything; a staff member should be able to pick any county and see why it ranks where it does; anyone comparing exact numbers uses the table. Today everything is shown at once at the same weight (plan, "What is wrong today"), so the answer is buried.

| Role | Gets (after a, b, c) |
|---|---|
| staff, admin | the map with its legend directly underneath, the five highest-need counties beside it, a short county panel on a pick, a nine-column table |
| board_viewer | the same page, same data, `BOARD` eyebrow (`NeedMapQuery.eyebrow`) |

## Decisions (designer defaults, inside George's plan)
1. Swatches carry no visible words; their names and hints carry band and count. The ramp reads as one bar with "Lower need … Higher need" under its ends, which is the convention for a sequential legend and fits 375 without wrapping.
2. The map is left-aligned in its column from 1024 (`preserveAspectRatio`), so the legend sits flush under it instead of under empty space.
3. With `?fas=1` the heading becomes `Highest need among FAS counties` so the list is never mistaken for the statewide top five.
4. The list's numbers explain themselves through one `ExplainLayer` (same attributes as the table cells), not one Radix root per number (polish bar X5); the name is the link so the 44 px row target never nests a button in a link.
5. `CountyPanel` imports `Swatch`/`fillFor` from `NeedMap.tsx` (a render-time cycle, harmless); moving the swatch to its own file is left for b to avoid churn here.

# DS-20b — County panel (selected county)

## Layout (top to bottom, all widths)
1. `h2` county name + `FAS county` badge (unchanged).
2. Rank line (`data-slot="rank-line"`), serif `text-xl`: `<place> of <N> counties scored · <band> band`; the place is the rank `ExplainCard`. Under it, small: `Need score <score> · version <v>`; the score is the need-score `ExplainCard`.
3. The serif comparison sentence (`NeedCompare.sentence`, unchanged).
4. `Key measures` (`h3`) + `CompareBars` for `KEY_MEASURES` present in the data, in that order; each row: label · value, bar with the median tick, `Higher than N of M other counties · state median X%`.
5. `<details data-slot="all-measures">`, closed: summary `All measures (<n>)` with a chevron that turns 90° (180 ms, `ease-out`; reduced motion handled globally), 44 px tall. Inside, one group per source and release: `h3` topic, the source line once (`Provenance`, `data-slot="source-footer"`), then label · value rows; key rates first in key order, other rates, then counts.

## Exact copy
- Rank: `Highest need of 26 counties scored · Highest need band` (rank 1); `3rd highest need of 26 counties scored · Highest need band`; ordinals 1st, 2nd, 3rd, 4th, 11th–13th, 21st, 22nd, 23rd.
- Unscored: `No need score, so no rank or band.` + `whyHidden` (`The source did not publish this for this county in that release.` or `This number appears once the data behind it is set up.`).
- Score: `Need score <±x.xx> · version <v>` (the old `· 26 counties ranked` is dropped: the rank line says it).
- `Key measures`; bar line `Higher than 22 of 28 other counties · state median 11.2%`; screen readers hear `9.2%, above the state median of 8.6%, higher than 22 of 28 other counties`.
- `All measures (13)`.
- Topics: `Census SAHIE` → `Health coverage`; `Census SAIPE` → `Poverty`; `Census ACS 5-year` → `Households and population`; any other source → its name. Source line: `<name> <vintage> · as of <Mon YYYY>`.
- Not published row: `<source> did not publish this for <county> in <vintage>.` (unchanged).

## Trust rules
No number, query or ranking changes. The ordinal comes from the stored rank string and the band from `bandName` over the stored bins. Every label keeps its `ExplainCard` with source, release and as-of; the `±` margin keeps its `Hint`. DESIGN need-map rule 5 now holds at group level (George decision 3): one group per source **and release**, so a heading never covers two releases.

## Accessibility
Native `<details>`/`<summary>`: Enter and Space toggle, the expanded state is announced; the summary is 44 px at every width. Panel `h2` → `h3` (Key measures, topics). The bar sub-line stays `aria-hidden`; its words are in the `sr-only` text. axe 0 serious/critical at 375/1024/1440 in light and dark, closed and open (local render, 12 runs); `scrollWidth` equals the viewport.

## Decisions (designer defaults)
1. The rank line is the panel's one serif headline (`text-xl`; `text-2xl` wrapped to three lines at 375). The comparison sentence stays serif at body size as its supporting line.
2. Bars and the sentence use the same `NeedCompare.rows`; only the bars are limited to the key five, so the sentence still leads with whichever rate stands out.
3. The bar sub-line drops the repeated value and leads with the comparison; the state median moves to the end.
4. Groups split by release as well as source, so a source line is never wrong for a row under it.
5. The panel closed at 1440 is 690 px, not the plan's ~450: the five bars (about 300 px) and the sentence are kept as the plan describes. Getting to 450 would mean dropping the sentence or the sub-lines; not done without a call.
