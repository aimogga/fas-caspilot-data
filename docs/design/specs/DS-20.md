# DS-20 — Foundation grants: the page says what to add and why, every field explains itself, every value in the recent list explains itself, and the page loads into a skeleton
Source docs: `docs/design/POLISH_PLAN.md` row DS-20; `docs/design/fas-screen-plan-part2.md` §4 P2 "Foundation opportunity form + CSV import: same mapping pattern as the upload wizard"; no mockup exists for `/staff/grants`; `.claude/skills/design-polish/references/*`; DS-07 (the `Manual entry` tag, public opportunity dates may show the day), DS-15 (`MANUAL_HINT`), DS-18a/18b (header in words, per-field helper words in a pure module, the dashed upload dropzone), DS-14 (`PageSkeleton`), DS-13b (focusable value targets under one `ExplainLayer`).
**Depends on:** DS-09 explain kit, DS-11a `ExplainLayer`, DS-14 `PageSkeleton`, DS-19 dark mode (all on main). **Budget:** ≤ 400 hand-written lines (D-012); estimate 340, one PR. **Before/after shots:** taken by the supervisor (`/staff/grants` as staff at 375/1024/1440, light and dark, plus 1024 hover on an award value).
**ID note:** open PR #286 plans a different "DS-20" (need map declutter). This packet was assigned DS-20 by the supervisor; see Open questions 1.

## Purpose and users
Staff add foundation grants the automatic Grants.gov search never finds. Between calls they need to know, beside every field, what to type, in what format and which rule it must keep, and to trust the list of what was already added: what the award range means, what "No close date" or "Award not stated" says about the listing, and what the `Manual entry` tag means.

| Role | Gets |
|---|---|
| staff, admin | eyebrow + serif H1 in words + one sentence; a helper sentence under every form field in `aria-describedby`; the import in a dashed dropzone with its own help sentence; every award, close date, missing funder and `Manual entry` tag in the recent list explains itself on hover, focus and tap; a footer sentence that repeats the fallbacks in words; an error with a reference id and Try again; a skeleton while the server renders |
| board_viewer | 403 (unchanged) |

## Scope (sub-packet a, the whole page)
- Header: eyebrow `Foundation grants`, H1 `Add the grants foundations publish`, one sentence.

- `FoundationForm`: helper sentence under each control (`fo-<key>-hint`), listed in `aria-describedby` before the error id; placeholders removed (the sentence replaces them); card title `Add one grant`; failures through `saveFailure` so no table name reaches a user.
- `FoundationImport`: the file input inside the DS-18a dropzone classes with `fo-file-help`; "2 000" → "2,000"; a fix sentence in the error preview; failures through `importFailure`.
- Recent list: one `ExplainLayer`; per row the title, the `Manual entry` badge (target), the funder (target only when missing), the award range and the close date (targets, tabular); rows stack at 375 and put award and close date right-aligned from 768; footer sentence; error state now `ErrorState` with a reference id; empty state in words. The query now also reads `source` and the stored `raw.imported_at` month.
- `app/(app)/staff/grants/loading.tsx` via `PageSkeleton`; route added to `lib/status/skeleton.test.tsx`.
- Out of scope: `/staff/grants/matches`, a textarea primitive for the long fields, editing or deleting an entry, DS-18c, other routes' loading files.

### First impression (critique)
The page reads as a form, not a finished page: the eyebrow is the nav group (`WORKSPACE`), the H1 the nav label. The form hides its rules in placeholders that vanish on typing and say nothing for title, funder, money, notes or description. The recent list is a row of grey text: nothing says what an award range is, what "No close date" or "Award not stated" means, or what `Manual entry` means; imported rows carry the same tag with no way to tell them apart. A load failure is shown as an empty state without a reference. Server failures can show "Could not save to opportunity".

## Exact copy
- Eyebrow `Foundation grants`; H1 `Add the grants foundations publish`; sentence `Grants.gov opportunities arrive on their own; foundation grants do not. Add each one by hand or import a list, and it starts in the grant pipeline as New.`
- Field help: `FORM_HELP` in `lib/grants/form-words.ts`.
- Import: `One row per grant, up to 2,000 rows or 2 MB. Use the template so the columns match the form; separate list items with semicolons.`; dropzone `Drop a CSV here or choose one from your computer. Every row is checked before anything is saved.`; preview fix `Nothing is imported until every row passes. Download the error report, fix those rows and choose the file again.`
- Terms: Manual entry = `MANUAL_HINT`; Award range `The smallest and largest single award the funder says it will make, as written in its listing. When only one end is given, only that end is shown.`; Close date `The last day the funder accepts applications, as its listing states it.`; Funder `The foundation or organization that gives the grant.`
- Hidden reasons: award `The listing did not state an amount, so none was entered. It is never shown as $0.`; close `The listing gave no close date. It may take applications at any time; check the funder’s page before planning around it.`; funder `This entry was saved without a funder name.`
- Source row: `Typed in by FAS staff` or `Imported by FAS staff from a list`; as-of row: the stored added month (`Oct 2026`).
- Footer: `The 10 newest grants, as each funder published them and entered by FAS staff. “No close date” and “Award not stated” mean the listing did not say; neither is read as a passed deadline or $0.`
- Skeleton: `Loading foundation grants. The page appears in a moment.`

## States
Empty, loading, error (reference + Try again), save failure, import failure, validation (unchanged), saved (unchanged), 403 (unchanged).

## Trust rules
Every value comes from the stored `opportunity` row; the added month comes from the stored `raw.imported_at` and is left out when absent. A missing award or close date is words with a reason, never `$0` or blank; a 0 floor reads as no floor (`awardRange`). Opportunity dates show the day (public listing, DS-07). Helper sentences name only rules `validateFoundation` and the API enforce (required, length, both date formats, date order, dollar format, floor ≤ ceiling, URL prefix, semicolons, the funder + title + close date unique index). "Starts in the grant pipeline as New" is what `FoundationHttp.post` writes. No claim about matching.

## Accessibility
Each control lists `fo-<key>-hint` (then `fo-<key>-err`) in `aria-describedby`; the file input lists `fo-file-help`. List values are focusable (`tabIndex=0`) spans with a visible 2 px focus ring, 44 px tall below 1024; one `ExplainLayer` shows the card on pointer, focus and tap, pins it as a `dialog` on Enter or tap, closes on Escape and returns focus; a polite live region reads it. The words also live in the row text and the footer sentence. axe 0 serious/critical and `scrollWidth` ≤ width at 375/1024/1440 in light and dark.

## Decisions
1. The tag stays `Manual entry` on imported rows too (DS-07, D-019: both are hand-entered foundation lists); the card's value row says `Added by hand` or `Imported from a list`.
2. Value targets are tab stops (the DS-13b board precedent) rather than arrow-key-only cells: the list holds at most 10 rows and ends the page.
3. A new e2e file rather than more steps in `foundation-import.spec.ts`, so the flow test stays a flow test; the flow test only had its words updated.
4. The e2e row uses a far close date so it sorts into the newest 10 (the list orders by added month, then close date); the "No close date" fallback is covered by the unit test and the import flow.
