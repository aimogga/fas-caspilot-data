**Scope**

- Sidebar: 256px; full 256px sidebar at ≥ 1024px; a 56px icon rail at 768–1023px; below 768px, a top bar plus nav sheet (see Mobile layout).
  - FAS Evidence wordmark ("FAS" Source Serif 4 Bold, a 1.5px primary rule, "EVIDENCE" Inter 600 caps with 0.2em tracking) and a "Family Advocacy Services" line.

- `/staff`, `/admin` and `/board` render inside the shell. Their content stays placeholder, using `PageHeader` + `EmptyState`.

**Acceptance**

2. Screenshots for staff and board at 1440 and 1024.
3. No "Role: X" text in the page body.

5. axe clean; keyboard can reach every nav item.

## Mobile layout (375px; below 768px)
Mockups: `docs/design/mockups/p0-staff-home-375.png` (closed), `docs/design/mockups/p0-staff-home-375-nav-open.png` (sheet open).
- Sidebar is removed from the flow. A sticky **top bar** replaces it: height 56px, padding 0 12px, `bg-background`, bottom border.
  - Left: **menu button** 44×44, 1px input border, radius 8, hamburger icon, `aria-label="Open navigation"`, `aria-expanded`, `aria-controls="nav-sheet"`.
  - Center-left (flex:1): "FAS Evidence" wordmark, 12px gap after the button.
  - Right: avatar 32px inside a 44×44 hit area, opens the account menu (name, role, Sign out).
- The desktop top bar's breadcrumb row sits below as a second row (padding 8px 16px, wraps); freshness chip and SYNTHETIC badge wrap under it; user name block is hidden (moved to the account menu).
- **Nav sheet** (shadcn `Sheet`, side=left): width 300px (max 85vw), full height, `bg-sidebar`, shadow-lg, scrim `oklch(0.22 0.012 70 / .45)`.
  - Header: wordmark + org line; close button ✕ 44×44 top-right.
  - Same role nav groups as desktop (staff/admin/board per IA); items 44px min height, 15px text; active item uses the same left rule + tint as desktop and `aria-current="page"`.
  - Behavior: opens on menu tap; focus moves to the first nav item; focus trapped; Esc, ✕, scrim tap or route change close it; focus returns to the menu button; body scroll locked while open. Motion 200ms slide, none under `prefers-reduced-motion`.
- Tablet (768–1023) shows the 56px icon rail; desktop (≥ 1024) shows the full 256px sidebar.
- Acceptance additions: Playwright at 375 — menu visible, sheet opens/closes via button, Esc and scrim; each role sees only its nav; `scrollWidth <= 375`; axe 0 serious/critical with sheet open and closed; screenshots at 375 (closed + open), 1024, 1440.

**Mobile hard requirements (QA-checked at 375):** labels stacked above full-width fields; ≥ 16px side padding on login and pages; input text ≥ 16px; every tappable control ≥ 44×44px; no horizontal scroll. Contrast meets WCAG 2.2 AA (text 4.5:1, large text/UI 3:1).

## Page container adoption (intended layout change)
This screen adopts the DS-01c `Page` container (`[data-slot=page]`) in the main column of `AppShell`, which replaces the legacy `PageLayout` 800px centred column (`maxWidth: 800px; margin: 50px auto; padding: 20px`). Gutters are 16px below 768, 24px at 768–1023 and 32px at 1024 and up, with 20px top and 40px bottom.

- **What 1200 means.** 1200px is the `Page` container's **outer** max width, gutters included (this matches DS-01c and PR #37). The content box is 1200 − 2 × 32 = **1136** at most. All figures below are measured from the viewport's left edge, with the sidebar or rail included.

**Expected visual change. This is intended; QA judges against it, not pixel parity with main.** The role pages (`/admin`, `/staff`, `/board`) move from an 800px column with a 50px top margin into the app shell: the sidebar (256px at ≥ 1024, a 56px rail at 768–1023, a top bar plus sheet below 768) and the main column. The heading moves down and right of the sidebar, and the page gets wider.

**Layout figures (signed in, inside the shell):**

| Viewport | Left of main column | Main column | Gutter | h1 left edge (viewport x) | Content width |
|---|---|---|---|---|---|
| 375 | top bar only, no sidebar | 375 | 16 | **16** | **343** |
| 800 | 56px rail | 744 | 24 | 56 + 24 = **80** | 744 − 48 = **696** |
| 1024 | 256px sidebar | 768 | 32 | 256 + 32 = **288** | 768 − 64 = **704** |
| 1440 | 256px sidebar | 1184 | 32 | 256 + 32 = **288** | container 1184 (under the 1200 cap), content 1184 − 64 = **1120** |

- **Playwright:** on every role page, assert the h1 `getBoundingClientRect().left` is 16 / 80 / 288 / 288, and the `[data-slot=page]` content width (`clientWidth` − horizontal padding) is 343 / 696 / 704 / 1120 at 375 / 800 / 1024 / 1440. At 1440, also assert the container is 1184 wide. At 375, assert the top bar is present and the sidebar isn't in the flow. `scrollWidth` equals the viewport at every width.
- **Layout-parity test (required).** This PR updates `tests/e2e/layout-parity.spec.ts` with the new expected h1 left edge and content width for its own screens (`/admin`, `/staff`, `/board`), using the figures above. It must not delete the test, skip any screen, or loosen tolerances. Screens this PR doesn't move (`/login`, `/403`, `/404`, the error page and `/`) keep main's values unchanged.
- **Body padding stays.** This PR does **not** remove the DS-01a global `body { padding-inline: 16px }`. It neutralises the padding only for `Page` screens with `body:has(> [data-slot=page]) { padding-inline: 0 }` (add the rule if it isn't already on main), so the gutter is applied once on `Page` screens. Screens still on the legacy layout after this PR keep the body padding and must stay pixel-identical: `/login`, `/403`, `/404`, the error page and `/`. DS-04 removes the body padding when it moves the last of them.
