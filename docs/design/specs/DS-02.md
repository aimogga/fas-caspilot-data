## Mobile layout (375px; below 768px)
Mockups: `docs/design/mockups/p0-staff-home-375.png` (closed), `docs/design/mockups/p0-staff-home-375-nav-open.png` (sheet open).
- Sidebar is removed from the flow. A sticky **top bar** replaces it: height 56px, padding 0 12px, `bg-background`, bottom border.
  - Left: **menu button** 44×44, 1px input border, radius 8, hamburger icon, `aria-label="Open navigation"`, `aria-expanded`, `aria-controls="nav-sheet"`.
  - Center-left (flex:1): "FAS Evidence" wordmark, 12px gap after the button.
  - Right: avatar 32px inside a 44×44 hit area, opens the account menu (name, role, Sign out).
- The desktop top bar's breadcrumb row sits below as a second row (padding 8px 16px, wraps); freshness chip and SYNTHETIC badge wrap under it; user name block is hidden (moved to the account menu).
- **Nav sheet** (shadcn `Sheet`, side=left): width 300px (max 85vw), full height, `bg-sidebar`, shadow-lg, scrim `oklch(0.22 0.012 70 / .45)`.
  - Header: wordmark + org line; close button ✕ 44×44 top-right.
  - Same role nav groups as desktop (staff/admin/board per IA); items 44px min height, 15px text; active item uses the same left rule + tint as desktop and `aria-current="page"`.
  - Behavior: opens on menu tap; focus moves to the first nav item; focus trapped; Esc, ✕, scrim tap or route change close it; focus returns to the menu button; body scroll locked while open. Motion 200ms slide, none under `prefers-reduced-motion`.
- Tablet (768–1023) shows the 56px icon rail; desktop (≥ 1024) shows the full 256px sidebar.
- Acceptance additions: Playwright at 375 — menu visible, sheet opens/closes via button, Esc and scrim; each role sees only its nav; `scrollWidth <= 375`; axe 0 serious/critical with sheet open and closed; screenshots at 375 (closed + open), 1024, 1440.

**Mobile hard requirements (QA-checked at 375):** labels stacked above full-width fields; ≥ 16px side padding on login and pages; input text ≥ 16px; every tappable control ≥ 44×44px; no horizontal scroll. Contrast meets WCAG 2.2 AA (text 4.5:1, large text/UI 3:1).

## Page container adoption (intended layout change)
This screen adopts the DS-01c `Page` container (`[data-slot=page]`): max content width 1200px (see below), centred in the available column; side gutters of 16px below 768, 24px at 768–1023 and 32px at 1024 and up; 20px top and 40px bottom. In the same PR it **drops** the DS-01a global `body { padding-inline: 16px }` and the legacy `PageLayout` 800px centred column (`maxWidth: 800px; margin: 50px auto; padding: 20px`). `AppShell` replaces `PageLayout`, and pages render inside `Page` in the main column next to the sidebar, so the gutter is applied exactly once.

- **What 1200 means.** 1200px is the maximum *content* width, measured inside the gutters. The gutters sit outside it, so the `Page` container's outer max width is 1200 + 2 × gutter (1264px at ≥ 1024). Content is narrower than 1200 whenever the available column is narrower than that.

**Expected visual change. This is intended; QA judges against it, not pixel parity with main.** The role pages (`/admin`, `/staff`, `/board`) move from an 800px column with a 50px top margin to the app shell. That means the sidebar (256px at ≥ 1024, a 56px rail at 768–1023, a top bar plus sheet below 768) plus a full-width main column, with content capped at 1200px and DS-01c gutters. The heading moves up and left, and the page gets wider.

**Layout figures (signed in, inside the shell):**

| Viewport | Chrome left of `Page` | Gutter | h1 left edge | Content width |
|---|---|---|---|---|
| 375 | top bar only (no sidebar) | 16 | **16** | 375 − 32 = **343** |
| 800 | 56px rail | 24 | 56 + 24 = **80** | 800 − 56 − 48 = **696** |
| 1024 | 256px sidebar | 32 | 256 + 32 = **288** | 1024 − 256 − 64 = **704** |
| 1440 | 256px sidebar | 32 | 256 + 32 = **288** | 1440 − 256 − 64 = **1120** (under the 1200 cap) |

- **Playwright (signed in, every role page):** assert the h1 `getBoundingClientRect().left` is 16 / 80 / 288 / 288 and the `[data-slot=page]` content box (`clientWidth` − padding) is 343 / 696 / 704 / 1120 at 375 / 800 / 1024 / 1440. At 375, assert the sidebar is not rendered in the flow and the top bar is present. `scrollWidth` equals the viewport at every width. Before/after screenshots are attached to the PR.
