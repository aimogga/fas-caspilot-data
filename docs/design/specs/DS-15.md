# DS-15 — Team dashboard: every cell, filter, stage and trend point explains itself
Source docs: `docs/design/targets/visual-direction.md` (the bar; no dashboard artboard, so the mockup is primary); `docs/design/POLISH_PLAN.md` rows DS-15a and DS-15b; `docs/design/fas-screen-plan-part2.md` §4 P1-1 (team dashboard); mockup `docs/design/mockups/p1-team-dashboard.png`; `.claude/skills/design-polish/references/*` (bar, plain language, audit, evidence); DS-07 (cards, M4 table, copy and states); DS-09 (explain kit); DS-11a (`ExplainLayer` on a table); DS-10b (`LineHover` beside a small chart); DS-14 (`loading.tsx` and skeletons, PR #262, not repeated here).
**Depends on:** DS-09 kit, DS-11a `ExplainLayer`, DS-10b `LineHover` on main. **Budget:** ≤ 400 hand-written lines per sub-packet (D-012). **Before and after shots:** taken by the supervisor from production and the preview (no `/dashboard` before shots existed; this shell has no Supabase or preview access).

## Purpose and users
The staff page that says whether FAS help is working, ready to cite. A case manager between calls must be able to hover, focus or tap any number in the income-band table, any filter label, any pipeline stage and any quarter on the trend line and read what it means, where it comes from, the as-of month, and why a cell is hidden, in words that survive being read aloud.

| Role | Gets |
|---|---|
| staff, admin | `/dashboard` with the hover layer on M4, hints on filters and pipeline stages, the crosshair on the M1 trend, deltas with a hint |
| board_viewer | 403 (unchanged; the board reads `/board`) |

## Scope (sub-packet a only)
- `lib/dashboard/words.ts` (pure): the M4 cell terms (`m4_completed`, `m4_closed`, `m4_rate`), `m4Cell` → the `data-*` attributes one `ExplainLayer` reads off a cell (term, value, source, as-of, why hidden: small count vs complementary via `whyHidden`), `FILTER_HINTS` (one sentence per filter), `STAGE_WORDS` (one sentence per pipeline stage, sourced from `STAGES` in `lib/dashboard/query.ts`; a count sentence is appended), `MANUAL_HINT`, `deltaHint` (reuses `chip` from `lib/staff/home.ts`), `m1Stats` (the distribution line without the `pct` code).
- `M4Table`: wrapped in one `ExplainLayer` inside a keyboard region (arrow keys walk the cells, as the need table); every count and rate cell, the complementary row and the total row carry the attributes; the words also stay in the cells and the footer.
- `FilterBar`: an Info `Hint` beside Quarter, County, Referral source and Compare to prior quarter (both the inline bar and the sheet copy).
- `PipelineWidget`: each stage name is a `Hint` trigger (dotted underline) with its sentence and the count in words; the `Manual entry` badge gets a `Hint`.
- `TrendLine`: `LineHover` mounted beside the 64 px SVG (pointer crosshair, arrow keys, polite live region); `LineHover` gains a `className` so a small plot can size it (default unchanged for `LineChart`).
- `MetricCard`: the delta line becomes a `Hint` trigger when `deltaHint` is given; `metric-props` supplies it for M1, M2, M3 and M5 and swaps the M1 `25th pct` line for words.
- `tests/e2e/dashboard.spec.ts` (new): one test per criterion for CI.
- Out of scope (DS-15b): M6 share bar hover with keyboard walk, O1 rows, the "View as table" hint, deltas elsewhere. Out of scope (shipped by DS-14, PR #262): `app/(app)/dashboard/loading.tsx` and the skeleton.

## Exact copy

## Decisions
- The complementary row keeps its one-cell `Hidden · protects another cell` text (pinned by DS-07c tests); the reason in full lives in the card and the glossary.
- M4 column headers are not made triggers this packet: the cell cards already name the column (term title), and the headers stay plain `th scope="col"` so M6 and O1, which share `Th`, are untouched until DS-15b.
- Filter hints use the Info icon face rather than making the `<label>` the trigger, so the label keeps pointing at its select.
- The delta text stays `… than Q2` (shared `format.delta`, used by the board); the hint carries the quarter in full.
- `LineHover` gets a `className` prop with its old classes as the default rather than a second component (DS-10b left this gap).

## Open questions
1. Income bands come through as stored codes (`a`, `b`, `c` in the seed); the mockup's `Under 100% FPL` names need the band vocabulary FAS uses, which is not in the data yet.
2. The pipeline sentences describe each status in plain words; if FAS uses the stages differently (for example "Passed" as "passed to a partner"), the words change in `STAGE_WORDS` only.
3. `tooltipText` says `Hidden (n < 11)`; the plain-language table prefers the full sentence. A kit change (`lib/charts/hover.ts`) is shared with every chart and is left for a kit packet.

## Decisions
- The bar segments became labelled `role="img"` targets rather than staying `aria-hidden`: a focusable element inside `aria-hidden` is an axe serious violation, and the packet asks for a keyboard walk across the segments.
- The share phrases above the bar are targets too, so a hidden share (no bar) still explains itself in place.
- The hint label is `About the table view` to keep `View as table` an exact, unique button name across the dashboard, board and packet specs.
- The hint sits inside a `print:hidden` span: the print sheet forces `[data-slot=hint-trigger]` to `display: inline`, which would otherwise print the Info glyph.
- `KEYS` is exported from `M4Table` rather than moved to `words.ts`, so DS-15a's markup test and file stay as they are.
