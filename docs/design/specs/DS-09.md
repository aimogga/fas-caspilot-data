## Purpose and users
George's rule (2026-10-15, D-040): every number, badge and status chip in the app shows, on pointer hover, on keyboard focus and on tap, a small card with what it means in plain words, the source, the as-of date and why a value is hidden. This packet builds the kit and wires the shared trust components so that every page packet from DS-10a on only adds terms and triggers.

| Reader | Gets |
|---|---|
| Board member who has never read a chart | Plain words on every number, the source and the date, without leaving the page |
| Staff between calls | The same words, plus the stored-row ids (source id, ingest run, vintage) behind a footer |
| Screen-reader and keyboard users | A real `role="dialog"` on Enter or Space, labelled by its title, Escape returning focus; the hover faces are an extra, never the only path |

## Components
**Reused:** `Badge`, `Card*`, `Alert*`, `Cluster`, `Section`, `asOfNote` (`lib/dashboard/cards`), `METRIC_CARDS`, lucide `Info`, the `CHIP` 44 px inline-trigger precedent (`components/freshness/AggregateFreshnessChip.tsx`).

**New (`components/trust/explain.tsx`, `"use client"`):**
- `ExplainBody({ term, titleId?, value?, source?, asOf?, hidden?, rows? })` — pure markup: `<p class="font-medium">` title, `<p class="text-sm">` plain words, then a `<dl>` with only the rows given, in this order: Value, Source, As of (through `asOfNote`, so a missing date reads "date not available yet"), any extra rows, "Why it's hidden". Its root carries `data-slot="explain-content"`, so both faces of an `ExplainCard` contain it.
- `ExplainCard({ term: TermId | Term, value?, source?, asOf?, hidden?, rows?, label?, side?, icon?, className?, children? })` — one `<button type="button" aria-haspopup="dialog" data-slot="explain-trigger">` is both the Radix HoverCard trigger (`openDelay` 150, `closeDelay` 100) and the Radix Popover trigger (nested `asChild`). The hover card is controlled (`open = hover && !popoverOpen`), so it stays closed while the dialog is open and is reset when the dialog closes. The popover content has `role="dialog"` (Radix default) and `aria-labelledby` the body title. `icon` renders lucide `Info` with `aria-label={label ?? "About <title>"}`, `w-11 shrink-0 lg:w-auto` so a flex parent's `[&>*]:min-w-0` cannot collapse it. Text triggers get `underline decoration-dotted underline-offset-4`.
- `Hint({ text, label?, className?, children })` — the same single-trigger pattern with a Radix Tooltip (hover and focus) and a Popover (click, tap, Enter, Space); the popover content gets `aria-label={text}` and shows the same string; `data-slot="hint-trigger"`.
- `Provenance(SourceFooterProps & { detail?: { sourceId?, ingestRunId?, lastSuccessAt?, vintage? } })` — an `ExplainCard` on `sourceTerm(source)` whose rows are Source, As of, Period, n and the detail fields when present; its trigger is the footer text itself.
- Trigger classes: `inline-flex min-h-11 min-w-11 items-center justify-center rounded-md text-left lg:min-h-0 lg:min-w-0`. Faces: `max-w-[20rem] text-sm` on `bg-popover`, 1 px border, `shadow-md`, radius md.

## Behaviour matrix
| Input | `Hint` | `ExplainCard` (text or icon) | `Provenance` (footer text) |
|---|---|---|---|
| Pointer hover | Tooltip opens at once (provider delay 0), closes when the pointer leaves the grace area | Hover card opens after 150 ms, closes 100 ms after leaving | Same as ExplainCard |
| Keyboard Tab (focus) | Tooltip opens on focus, closes on blur | Hover card opens on focus (Radix opens on focus), closes on blur | Same |
| Enter / Space (click) | Tooltip closes; popover `role="dialog"` opens with the same string; focus moves into it | Hover card closes; popover `role="dialog"` labelled by the title opens with the same body | Same, with the stored-row ids |
| Escape | Dialog closes, focus returns to the trigger | Same | Same |
| Tap (touch) | Pointer events of type touch never open the tooltip; the tap's click opens the dialog | Same (the HoverCard trigger's `touchstart` preventDefault is a no-op under React's passive listener; verified by the `hasTouch` test) | Same |
| Tap or click outside | Dialog closes, focus stays where the user tapped | Same | Same |

## Exact copy
- Metric terms: titles exactly as `METRIC_CARDS`; plain words exactly as the core term table in `plain-language.md` (m1: "How many days a family waited between the court order and their first therapy session. We report the median, the middle value, so one very long wait cannot skew it.").
- `HIDDEN_SMALL`: `Fewer than 11 families, so the number is hidden to protect privacy.`
- `whyHidden`: suppressed → `HIDDEN_SMALL`; complementary → `Hidden so the smaller group next to it cannot be worked out from the total.`; not_published → `The source did not publish this for this county in that release.`; not_available → `This number appears once the data behind it is set up.`; error → `This number could not be loaded, so nothing is shown until the next try.`
- Sources: `FAS records`, `Census SAHIE`, `Census SAIPE`, `Census ACS 5-year`, `Grants.gov` each have a sentence; any other name reads `A public data source. The footer shows the period it covers and the date of our last successful load.`
- Row labels: `Value`, `Source`, `As of`, `Period`, `n`, `Source id`, `Ingest run`, `Last success`, `Vintage`, `Why it's hidden`.
- Icon label: `About <title>`. Visible footer text is unchanged: `<source> · <period> · n <n> · as of <Mon YYYY>`.

## States
- Closed: nothing in the DOM beyond the trigger (faces are portaled only while open), so SSR markup and existing text assertions are unchanged.
- Hover face open (pointer or focus): no role; dismissed by leaving, blur or Escape.
- Dialog open: `role="dialog"`, named by `aria-labelledby` (ExplainCard) or `aria-label` (Hint); the hover face is forced closed; `aria-expanded="true"` on the trigger.
- Hidden value: the body's last row says why (`whyHidden`); `MetricCard` passes it for suppressed, not-available and error states and withholds `asOf` for an errored card.
- Unknown term id: `term()` returns a term titled with the id and the sentence `No explanation is written for this yet.` instead of throwing in a render path.
- Reduced motion: the faces use the opacity-only `explain-fade` keyframe (and the global 0.01 ms rule).

## Trust rules
- Every word in a face also exists outside it: the footer text, the `n<11` cell with its sr-only sentence, the chip word, the card title. The card is never the only place (D-040, X4).
- `SuppressedCell` still never prints the count; the native `title` is gone so there is one source of words.
- Dates stay month or quarter in family data; `asOf` passes through unchanged.
- No new numbers are invented: `Provenance` only prints what the page supplies; `detail` rows are optional and omitted when absent.
- No product codes in user-visible text (glossary test); no CasePilot branding.

## Accessibility
- One `<button type="button" aria-haspopup="dialog">` per target; no nested interactive elements (the wrapped Badge and spans are inert).
- 44 × 44 px below 1024 (`min-h-11 min-w-11`, icon `w-11`); 2 px `--ring` focus outline from the base layer; `rounded-md` (chips `rounded-full`) so the ring follows the shape.
- Dialog named by its title (`aria-labelledby`) or the hint text (`aria-label`); Escape closes and Radix returns focus to the trigger; tap outside does not steal focus back.
- Tooltip text is also exposed by Radix through `aria-describedby` while open.
- axe 0 serious or critical with a popover open at 1280 and at 375; `scrollWidth` ≤ 375 with a popover open (`collisionPadding` 8).

## Decisions
1. Primitives hand-written, not `shadcn add`: the registry host is denied by the egress policy. They are minimal and count toward D-012; a later `shadcn add tooltip popover hover-card --overwrite` from a shell that can reach the registry would replace them without touching callers (same exports, same `data-slot` names).
2. One trigger, two Radix roots: nested `asChild` triggers on one `<button>`, with the hover face controlled so it never shows over the dialog. Chosen over a single popover with a "hover mode" because Radix's tooltip and hover-card already handle grace areas, delays and focus.
3. `data-slot="explain-content"` lives on `ExplainBody`'s root, not on the Radix content, so the primitives keep `popover-content` / `hover-card-content` for the motion rules and both faces still carry the hook.
4. Text triggers get the dotted underline by default (not only `Provenance`) so every explainable word reads as explainable; `Hint` triggers do not (chips and the hatched cell already read as marked).
5. `term()` accepts a string or a term and falls back instead of throwing; `ExplainCard`'s prop stays `TermId | Term` so callers with a literal id get completion, and `MetricCard` resolves `card.id` through `term()`.
6. The "As of" row strips the `as of ` prefix from `asOfNote` ("Sep 2026" / "date not available yet") to avoid "As of · as of".

## Open questions
1. **One `HATCH`.** `app/globals.css` `[data-slot=suppressed]`, `ChartFrame.HATCH` and `NeedMap.HATCH_CSS` still differ (angle, line colour, period). Not merged here: the kit used the budget (388 lines with hand-written primitives). TODO for DS-11a/b (need map) or a 30-line cleanup packet: one exported `HATCH` in `ChartFrame` (or a `.hatch` rule in globals) used by all three.
2. **Flex parents with `[&>*]:min-w-0`** (`Cluster`, `Stack`, `Grid`) override a text trigger's `min-w-11` when the trigger is a direct child. Page packets should give short triggers a wrapper or a width class as the icon variant does; `ExplainLayer` (DS-11a) avoids the issue for tables and maps.
3. **Hover card after Escape.** Closing the dialog returns focus to the trigger, which (by Radix design) opens the hover face again after 150 ms for keyboard users; it closes on Tab or Escape. Acceptable for v1; revisit if QA finds it noisy.
4. **Domain terms** (`lib/need-map/terms.ts`, `lib/grants/terms.ts`) are for their page packets; the core file is kit-only from here on (D-040).
