# DS-16a — Data freshness: sources in words, cadence and vintage explained, run detail for admins, summary on every width
Source docs: `docs/design/POLISH_PLAN.md` row DS-16a/b; `docs/design/targets/visual-direction.md` (shared rules: eyebrow → sentence → source line, one accent, type steps); `docs/design/fas-screen-plan-part2.md` §4 "Data freshness (`/data-freshness`, F-209)"; DS-05 (the page as built); DS-09 (explain kit); DS-10b (`sourceName`, `vintageWords`, the Public sources card precedent); `.claude/skills/design-polish/references/*`.

## Purpose and users
The page a staff member opens when the top-bar chip says something is wrong, and the page an admin opens to find the run behind it. It must say, for each public source, in words a non-data person can read aloud: what we have, when we last got it, how often we expect it, and whether that is fine.

| Role | Gets |
|---|---|
| staff | Sources in words, cadence and vintage explanations, dated status words, the summary sentence |
| admin | The same plus a "Latest load" cell: run id, started, finished, status in words, rows loaded |
| board_viewer | 403 (unchanged) |

## Scope (sub-packet a only)
1. Cadence `Hint` on each row: the stored cadence word plus "A new load is expected every N days" from the D-021 cycle table; when the stored word has no day count, or no cadence is stored, the hint says so and names the yearly fallback. Nothing invented.
2. Vintage cell as an `ExplainCard` (term "Latest vintage": what a vintage is, value, source in words, as-of = last good load, why "No load yet" when absent) using `vintageWords` from DS-10b.
3. Admin-only "Latest load" cell as an explain card on the run (run id in full, started, finished, status in words, rows loaded); staff never see run ids. Built on the same `ExplainCard` face `Provenance` uses (see Decisions).
4. Summary sentence visible at every width (today `hidden lg:flex`): "7 public sources: 1 failed, 1 stale, 1 with no load yet, 4 current." with the aggregate chip and a `Hint`. Status cell in words and dated: `Current · loaded Oct 12, 2026`, `Stale since Aug 14, 2026 · 60 days`, `Failed on Oct 12, 2026`, `Not published · no load yet`, each one `Hint` with a row-specific sentence.
5. Source column in words (`sourceName`), never a registry code; the stored `data-row` hook keeps the code for tests.
6. `loading.tsx`: skipped. `PageSkeleton` is not on main (it arrives with PR #262, which also owns `app/(app)/*/loading.tsx`); noted in Open questions.
Out of scope: `/methodology` (DS-16b), admin pause/resume, run detail route, any schema change.

## Exact copy
- Summary: `<n> public sources: <k> failed, <k> stale, <k> with no load yet, <k> current.` (zero counts omitted; singular `1 public source`). Chip hint: `The worst status across every source. The chip in the top bar shows the same thing.`
- Cadence hint: `<Word>: a new load is expected every <N> days. The source counts as stale once its last good load is older than that.` · unknown word: `The source is recorded as "<word>", which has no day count yet, so it counts as stale after the yearly cycle of 366 days.` · none: `No cadence is recorded for this source, so it counts as stale after the yearly cycle of 366 days.` Cell text: the word, or `Not recorded`.
- Vintage card: title `Latest vintage`; plain `vintageWords(x).hint`; Value `2024` or `No load yet`; Source `<name in words>`; As of `<last good load>`; Why it's hidden `vintageWords('—').hint` when absent.
- Status words: `Current · loaded <date>` · `Stale since <date> · <N> days` · `Failed on <run date>` (or `Failed` when the run date is unknown) · `Not published · no load yet`. Hints: `The newest release is loaded. The last good load was <date>, inside the usual cycle.` · `Overdue for a refresh: the last good load was <date>, <N> days ago, and this source usually updates every <cycle> days.` · `The last attempt on <date> failed, so the last good load, <date>, is what the app shows.` · `Nothing from this source has loaded yet, so nothing is shown for it.`
- Latest load (admin): cell `<started date> · <Succeeded|Failed|Running|Status word>` or `No load yet`; card title `Latest load`; plain `One attempt to fetch and store a release from this source. Every number loaded by it points back to this run.`; rows Run id, Started, Finished, Status, Rows loaded.
- Footer: `Public sources · as of <date>. A source is stale once its last good load is older than its usual cycle.`

## States
Current · stale · failed · not published per row; empty (no sources); error (failed load); 403. Nothing in the table is ever a bare `—`.

## Trust rules
Every word comes from `source_registry`, `ingest_run` and `public_indicator` rows; dates are the day a load ran (public-source metadata, so a day is allowed; no family data). Run ids reach admins only. No count, date or cadence is invented: an absent cadence says so; an unknown cadence word names the fallback rule.

## Accessibility
Every trigger is a 44 px kit button below 1024 with the visible focus ring; hover text = focus text = tap text; status never by colour alone (glyph + word); `th scope` on headers and row names; `scrollWidth` ≤ 375; axe 0 serious or critical at 375, 1024 and 1440.

## Decisions
- The chip word stays `Current` (glossary `fresh_current`, the top bar and the home card) rather than the plan row's `Fresh`, so one status has one word across the app; the dated words beside it carry the meaning.
- `Provenance` has fixed rows (period, n, source id, ingest run, last success, vintage) and no started/finished slot, and `components/trust/**` is read-only for page packets; the admin run cell therefore uses the `ExplainCard` face `Provenance` is built on, with run rows. Same look, same behaviour.
- Run dates stay day-precise: they are load metadata about public sources, never family data (DS-05 precedent).
- `FreshnessChip` is not used in the table because its hint is the generic glossary sentence; the table's chips carry the row's dated sentence in one trigger instead of two.
